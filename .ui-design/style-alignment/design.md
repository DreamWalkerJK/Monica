# Focused layout corrections

The operator needs to read object identity, compare adjacent work areas, and use
refresh or scope controls without losing the visual relationship between them.
This change addresses the reported component boundaries rather than redesigning
their surrounding workbenches.

## Project-unit dossier

The existing object identity remains the primary region: title, complete key,
declared metadata state, and description. A contiguous fact strip groups the
owner and real dependency/method counts. It becomes an owner row above three
count cells when space is limited.

The role map is Primary for identity and technical structure, Info for requirement
traceability, and Secondary for architecture relationships. All paint derives
from the active Monica palette. Metadata has a 12px minimum. Section icons
describe the subject instead of implying a numbered process.

The missing-requirements region uses the shared compact `MoContentState` within a
tonal, dashed surface. It states the existing absence without inventing an error,
coverage percentage, or recovery action. Requirements, references, configuration,
and method disclosures retain their original data and interaction owners.

## Other component boundaries

- Kafka cluster/topic identity shares a responsive definition-list surface.
- Schema disclosure headers start at the same inset as parameter evidence;
  `MoJson` owns its internal toolbar and source padding.
- Adjacent RAG and event-test work areas stretch to the same grid-row height.
- Execution-plan navigation fills the detail-determined row; its existing list
  remains the local scroll owner. Compact layouts keep the stacked behavior.
- Scope, refresh, subscription, and terminal controls use deliberate common
  heights, label rows, and helper-text placement.
- Related Kubernetes workloads use a native list without an extra list inset.
- Phone MCP table cells stack their label and evidence so the no-parameters
  value and schema remain in one readable column.

## Retained behavior and acceptance

No polling, permission, mutation, selection, loading, clipboard, or focus
ownership changes are part of these layout corrections. The newer stack-trace
viewer already addresses the reported partial red stripe and inserted line
breaks, and remains unchanged.

Browser review uses the actual source components in a separate local host with
explicit representative Kafka, Kubernetes, dossier, and exception fixtures.
It does not establish connectivity to a production cluster. The terminal is
inspected without executing commands.

Acceptance covers desktop, intermediate, and phone containment; aligned painted
control boundaries; full dialog content and bottom actions; relationship
navigation and Escape focus return; and Default/Grove in both modes plus an
expressive theme for the dossier. Raw measurements and screenshots belong to the
local review artifacts, outside the production source tree.
