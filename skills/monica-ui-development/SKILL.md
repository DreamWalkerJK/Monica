# Monica UI Development

Use `$monica-architecture` for UI module boundaries and page decomposition. For a focused UI change, inspect the owning component, its CSS, and the rendered DOM. Use `$monica-ui-audit` when the task asks for a compliance review or the change has a concrete cross-cutting risk. Use `$monica-ui-localization` for user-facing strings, resources, or registry keys; use `$monica-infra-ui` for consumer registration.

Put component layout and local presentation in `.razor.css`. A Blazor isolation selector does not automatically reach a child MudBlazor component root: scope a real HTML wrapper and use `::deep`. Compare compiled `*.bundle.scp.css` selectors with the live DOM when a class exists but a rule does not apply. Prefer MudBlazor primitives for menus, dialogs, drawers, and popovers. Use v9 async APIs (`ShowAsync`, `ShowMessageBoxAsync`) and the v9 converter contract. Read [CSS isolation workflow](references/css-isolation-fix-workflow.md) or [v9 migration](references/migration-guide-v9.md) when those issues arise.

Keep data initialization in `OnInitializedAsync` or `OnParametersSetAsync` and DOM-dependent interop in `OnAfterRenderAsync`. An incomplete await permits re-entry and disposal. Cancel component-owned work, observe late resource-producing tasks, stop JavaScript callbacks before disposing their .NET targets, and avoid interop that mutates DOM from `DisposeAsync`. Read [Blazor lifecycle guidance](references/blazor-best-practices.md) for ownership/interleaving, [auto-refresh pattern](references/auto-refresh-page-pattern.md) for polling, and [browser storage](references/browser-storage-guide.md) when persisting UI state. `IBrowserStorage` owns local/session storage; its runtime keys have the `mo:` prefix.

Use MudBlazor palette variables first and the approved `--mo-color-*` tokens for roles the palette cannot express. Keep component-specific selectors in the owning CSS, shared MudBlazor visuals in theme CSS, and shell sizing in layout CSS. The shell owns AppBar height and viewport scrolling; page CSS should use available parent height and local overflow. Runtime fonts and static resources stay local; ship WOFF2 rather than source TTF/OTF. Read [theme CSS](references/theme-css-guide.md), [offline assets](references/offline-requirements.md), and [Precision design language](references/monica-precision-design-language.md) only for the relevant work. For theme regressions use [theme pitfalls](references/theme-authoring-pitfalls.md); for dense tables use [adaptive list/table](references/adaptive-mudblazor-list-table-pattern.md).

When MudBlazor API or DOM behavior is uncertain, inspect the exact v9.0.0 source. `scripts/check_mudblazor_source.py` resolves `MUDBLAZOR_SOURCE_PATH`; the source is needed for source-dependent diagnosis or regenerating the variable catalog, not ordinary component edits. `scripts/sync_mud_css_variables.py` updates `.tmp/monica-ui-development/mudblazor-css-variables.json`; `scripts/validate_mud_css_variables.py --root <project-root>` checks CSS/Razor usage and offers `--fix` for deterministic substitutions. Use `scripts/font_downloader.py` or `scripts/subset_ui_font.py` when working on local font assets. Validate theme colors with the repository's `scripts/validate_ui_theme_tokens.py` when styling changes.
